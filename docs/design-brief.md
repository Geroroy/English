# 디자인 브리프: "오늘의 문장" 화면

원래 요청:

> 1. UI는 직관적이게, 화면에는 '오늘 배울 영어 문장 및 한국어 번역만 딱 띄워놓기'
> 2. 문장에 맞는 적절한 이미지와 함께

이 요청은 해석의 여지가 큽니다. 무엇을 남기고 뺄지, "이미지"를 어디서 가져올지, 다른 화면에도 적용할지가 정해져 있지 않습니다.
아래는 같은 의도를 Claude Code가 바로 실행할 수 있도록 구체화한 버전과, 그 근거가 된 다른 앱들의 사례입니다.

## 참고한 앱과 가져온 원칙

| 앱 | 화면 방식 | 가져온 원칙 |
|---|---|---|
| Cake | 하루 표현 하나를 짧은 영상 카드로 보여 주고, 그 아래 영어와 한국어를 크게 표시 | 첫 화면 = 오늘의 표현 카드 하나. 부가 정보 없음 |
| Duolingo | 한 화면에 과제 하나, 상단 진행 바, 하단 고정 큰 버튼, 일관된 일러스트 | 한 화면 한 가지, 엄지가 닿는 아래쪽에 주요 버튼 |
| Speak | 문장 하나를 화면 가운데 크게 놓고 듣기/말하기 버튼만 둠 | 문장이 화면의 주인공, 버튼은 최소 |
| Memrise | 표현마다 원어민 영상이나 사진을 붙여 상황과 함께 기억 | 문장마다 상황을 떠올리게 하는 그림 |
| 말해보카, 1일 1문장 류 앱 | 카드를 좌우로 넘기며 하루 분량(3~5개)만 학습 | 좌우 스와이프 + 점(•••)으로 분량 표시 |

## Claude Code에 줄 구체화된 프롬프트

```
홈("오늘" 탭) 화면을 "오늘의 문장" 카드 화면으로 바꿔 줘.

[화면에 남길 것 — 이것만]
- 작은 라벨 한 줄: "오늘의 문장 · Day N"
- 그림 1장 (카드 상단, 화면 높이의 약 1/3)
- 영어 문장 (가장 크게, 굵게, 가운데 정렬)
- 한국어 번역 (영어 아래, 한 단계 작고 연한 색)
- 🔊 듣기 버튼 1개
- 오늘 문장 3개를 넘기는 장치: 좌우 스와이프 + 점 표시(현재 위치) + ‹ › 버튼
- 맨 아래 큰 버튼 1개: "10분 연습 시작"

[홈에서 뺄 것]
- 학습 계획 목록, 작문 레벨 카드, 패턴 설명, 팁 → 진도 탭이나 학습 단계 안으로 이동

[이미지 규칙]
- 문장마다 상황이 떠오르는 그림 (예: "Can I get an iced americano?" → 커피, 얼음, 손 든 사람)
- 외부 이미지 서버 없이 오프라인에서도 보여야 함 → 이모지 3개(주인공 1 + 소품 2)로 장면 구성
- 레슨마다 고유 배경색, 라이트/다크 모드 모두 지원
- 문장 id로 그림을 찾는 별도 데이터 파일(js/scenes.js)로 분리해서, 나중에 실제 일러스트로 교체 가능하게

[다른 화면에도 같은 카드 적용]
- 학습 단계 "핵심 표현": 한 화면에 한 문장씩 같은 카드로, 팁은 "💡 팁" 버튼을 눌러야 보이게
- 복습 카드: 그림 + 한국어를 보여 주고, 영어는 "정답 보기"를 눌러야 보이게

[완료 기준]
- 휴대폰 폭(390px)에서 스크롤 없이 그림·문장·번역·버튼이 한 화면에 들어옴
- 모든 문장(표현 60개 + 조립 문장 60개)에 그림이 있는지 테스트로 확인
```

## 원래 요청과 달라진 점

- **"이것만"을 목록으로 못박음.** "딱 띄워놓기"만으로는 버튼, 라벨, 진행 표시를 남길지 알 수 없습니다. 남길 요소와 옮길 요소를 각각 적었습니다.
- **이미지 출처를 정함.** "적절한 이미지"는 사진 검색, AI 생성, 일러스트 등 해석이 갈립니다. 앱이 오프라인에서도 동작해야 하므로 이모지 장면으로 정하고, 나중에 교체할 수 있는 구조를 요구했습니다.
- **적용 범위를 정함.** 홈만 바꿀지, 학습과 복습 화면까지 같은 카드로 통일할지를 적었습니다.
- **확인 방법을 적음.** 화면 크기와 테스트 기준이 있으면 Claude Code가 결과를 스스로 확인할 수 있습니다.

## 나중에 실제 그림으로 바꾸려면

`js/scenes.js`는 문장 id(`"1-e0"` 등)를 그림에 연결합니다. 일러스트 파일(`images/1-e0.webp` 등)을 준비해 `sceneFor()`가 이모지 대신 이미지를 그리도록 바꾸면 됩니다.
